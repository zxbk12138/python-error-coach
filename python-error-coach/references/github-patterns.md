# GitHub Skill 设计参考

本文件记录设计参考，不作为运行时必须读取的教程。所有规则均已用自己的话重新组织，没有复制参考项目的实现正文。

## 参考项目

### OpenAI Skills Catalog

- 仓库：<https://github.com/openai/skills>
- 重点参考：`skill-creator`
- 可迁移原则：
  - 名称和描述用于低成本发现；
  - 主文件只保留核心流程与约束；
  - 只在需要时加载详细参考资料；
  - 避免创建无用途的占位目录；
  - 通过真实行为测试而不是措辞匹配验证。

### AI Tutor Skill

- 仓库：<https://github.com/Bhala-Srinivash/agent-tutor-skill>
- 许可证：MIT
- 可迁移原则：
  - 教学不能停在“解释清楚”，还要检查用户能否复述、应用和迁移；
  - “我懂了”不能作为掌握证据；
  - 答错时指出具体误区并换一个角度；
  - 测验题目不得提示正确选项。

### CodeTrain

- 仓库：<https://github.com/InferHaven/agent-skills/tree/main/codetrain>
- 许可证：Apache-2.0
- 可迁移原则：
  - 先判断用户想“直接做”还是“自己学”；
  - 一次一个小心智步骤；
  - 提示逐级增加，不直接交出答案；
  - 没有看到运行结果时，必须诚实说明；
  - 教学难度随水平调整，而不是固定一套流程。

### Structured Root-Cause Research

- 仓库：<https://github.com/meiiie/structured-root-cause-research-skill>
- 许可证：MIT
- 可迁移原则：
  - 区分直接观察和推断；
  - 比较竞争假设；
  - 优先做能区分假设的最小测试；
  - 证据不足时保留不确定性；
  - 不把第一个看起来合理的解释当成根因；
  - 输出证据摘要，而不是内部思维链。

### Feynman Tutor

- 仓库：<https://github.com/koukekoukej-glitch/feynman-tutor>
- 许可证：MIT
- 可迁移原则：
  - 使用学习者已经使用的词；
  - 不突然引入没有解释的术语；
  - 具体代码问题直接谈代码本身，不为炫技硬造类比；
  - 根据用户是想快速确认还是深入理解来调整对话长度。

### Karpathy Guidelines

- 仓库：<https://github.com/multica-ai/andrej-karpathy-skills>
- 许可证：MIT
- 社区讨论参考：<https://www.xiaoheihe.cn/app/bbs/link/8a3871e370bb>
- 可迁移原则：
  - 不隐藏困惑，不默默替用户做关键假设；
  - 优先使用解决当前问题的最小实现；
  - 只修改与请求直接相关的代码，不顺手重构；
  - 把模糊任务转成可验证的成功标准；
  - 对简单问题保持简短，不把规则本身变成长篇输出。

## 融合后的设计选择

本技能采用：

- 修错、教学、复习测验、规划与代码审查四种模式；
- 水平由真实代码证据判断；
- 最多三个竞争假设；
- 一次一个可执行步骤；
- 证据摘要代替内部推理草稿；
- 修复后做一次轻量掌握验证；
- 第三方库信息不足时限制推断；
- 运行结果必须来自用户或可见工具结果；
- 默认使用自然、简短的助教表达，只有在信息复杂时才使用结构化格式；
- 修改代码时保持最小改动，不顺手重构或添加未请求的抽象；
- Runoob 仅用于主题索引，不复制正文。

没有采用：

- 复杂本地数据库和跨会话画像；
- 独立 Web UI；
- 自建模拟判题服务器；
- 自动执行用户代码；
- 固定刷题数量或强制完整课程。

这些能力会显著增加平台依赖，超出本次作品的可靠范围。
