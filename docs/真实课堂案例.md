# 真实课堂案例：半价购物车

## 案例来源

案例来自 Python 前六课中的 `for` 循环作业 `loop.py`。原作业要求把一组价格乘以 0.5，保存到新列表，并输出新列表和元素数量。

真实学习过程中出现过两个问题：

1. 在 `.py` 文件中只写了 `len(new_prices)`，没有写 `print()`；
2. 新的 99、100 两个价格写在循环结束之后，因此不会参与已经完成的循环。

这两点都不会引发语法报错，却能造成“程序运行正常、结果却不完整”的现象，适合验证技能是否能处理无异常的逻辑问题。

## 修改前

```python
prices = [4, 6.5, 3]
new_prices = []

for p in prices:
    new_prices.append(p * 0.5)

print(new_prices)
len(new_prices)

prices = [4, 6.5, 3, 99, 100]
len(new_prices)
```

实际输出：

```text
[2.0, 3.25, 1.5]
```

问题：

- 列表只有原来 3 个价格的结果；
- 后面的 `len(new_prices)` 没有用 `print()`，所以数量不显示；
- Python 从上到下执行，循环结束后再修改 `prices` 不会让循环重新运行。

## 修改后

```python
prices = [4, 6.5, 3, 99, 100]
new_prices = []

for p in prices:
    new_prices.append(p * 0.5)

print(new_prices)
print(len(new_prices))
```

实际输出：

```text
[2.0, 3.25, 1.5, 49.5, 50.0]
5
```

## 在 TeleAgent 中的测试方式

### 第一轮

学生先提供修改前的三元素列表，并怀疑 `append()` 只追加了一部分。

期望行为：

- 不直接责怪 `append()`；
- 指出循环目前只会遍历现有的 3 个价格；
- 只让学生检查一个方向。

实测结果：

- 技能明确表示 `append()` 不是嫌疑人；
- 指出 `for` 只会遍历当前 `prices` 中的元素。

### 第二轮

学生补充：老师在循环后增加了 99、100，然后才打印新列表。

期望行为：

- 撤回原来的 `append()` 怀疑；
- 将原因更新为代码执行顺序；
- 给出一个验证步骤。

实测结果：

- 技能正确更新判断；
- 解释新赋值不会让已经结束的循环重跑；
- 继续保持一次一个下一步。

## 可放进演示视频的结论

程序不报错不等于程序结果正确。该案例能同时展示：

- 文件模式需要 `print()` 才显示结果；
- Python 从上到下执行；
- 新证据出现后，技能会修改原来的假设；
- 学生能通过比较 3 项和 5 项输出理解代码顺序。
